## Proposed design

Extend src/components/ui/modal.tsx as the single React modal foundation. Keep feature state, data fetching, validation, and content in feature components; eliminate feature-owned backdrops, dialog containers, close controls, header/footer layout, focus traps, and shell CSS. Use explicit typed props and content slots rather than arbitrary shell-class overrides. Retain the established breadcrumb header and semantic tokens.

Proposed props: open, onClose, title or breadcrumb, description, size (compact/standard/wide/reader/workspace), presentation (dialog/sheet/fullscreen), dismissible, busy, initialFocusRef, footer metadata, footer actions, and children. Final names should follow the existing API and minimize redundant switches. A single dismissal policy must govern close button, Escape, and backdrop; trapping remains active during a pending mutation. Preserve nested portal ownership, focus return, safe initial focus for destructive confirmations, accessible names/descriptions, and native browser-pane lifecycle hooks.

The existing Modal already provides portals, nested portal registration, focus trapping, breadcrumbs, and footer slots. It currently supports only a wide boolean, and Escape/backdrop switches do not themselves govern the close button. Each caller must be reviewed before replacing busy-state guards. ConfirmProvider is already a Modal consumer and should remain a thin behavior adapter.

Approaches considered: (1) extend existing Modal with typed presentation and layout variants (recommended; preserves proven nested portal behavior); (2) introduce a replacement modal framework (requires re-proving existing lifecycle contracts); (3) mechanically wrap bespoke shells (retains layout duplication and does not satisfy the requested end state).

Nonmodal anchored popovers must be classified by actual interaction semantics before migration. Shared Popover remains their canonical foundation. Native SwiftUI sheets and OS startup dialogs cannot consume a React component; inventory them separately and apply equivalent platform-specific consistency without replacing native behavior.

## Builder-review decisions

The independent read-only review confirms the existing foundation can own all web modal shells, provided the following lifecycle requirements are preserved. These are implementation decisions within the approved direction, not evidence that migration has happened.

- Retained mounting: closed MobileDrawer content stays mounted, hidden/inert, and untrapped. Default Modal behavior remains unmount-on-close. Hidden-owner context continues closing descendant portals.
- Focus: support explicit initial focus and a late-bound restoration gate. FirstProjectGate transfers focus to Tasks on that exit; onboarding can temporarily yield focus to diagnostics without losing its contents.
- Presentation: dialogs, left/right sheets, and fullscreen share chrome and focus. Inline-to-modal content must not lose iframe, selection, draft, or scroll state unnecessarily; normal inline panels remain nonmodal.
- Dismissal: one reason-aware request-close function handles Escape, backdrop, and close controls. Pending mutations disable all user dismissal without disabling focus containment. Per-channel switches remain for capture modes and required gates. Move modal Escape ownership out of parallel global handlers as each surface migrates.
- Portal ownership: retain complete backdrop registration, root/depth contexts, descendant portal registration, and Popover coverage. Native Tab recapture is a supported focus-trap option, required for iframe/media surfaces.
- Visual stack: preserve native webview coverage and reconcile nested modal/popover visual order with keyboard ownership. Define the affected background region before applying inert/scroll locking; a pane-scoped project gate must not silently become app-blocking.
- Imperative callers: use a React host rendering Modal, not a second DOM modal engine. Retain opener and ownership context when launched from rendered Markdown.

The source pass found two high-priority gaps to cover with behavior tests: the shared header close button bypasses busy-related Escape/backdrop switches, and migration-review/reader-source dialogs lack their own trap. WorkspaceRailSheet's trap is owned by its controller and must be moved, not duplicated. Some declared aria-modal surfaces are anchored popovers with interactive backgrounds and need corrected semantics.

Accessibility acceptance follows Cave's design language and the [WAI modal dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/): move focus inside, contain keyboard navigation, provide an accessible name and a visible dismissal route where the workflow permits it, restore focus appropriately, and prevent background interaction for true modals. Choose initial focus by content and consequence; long structured documents should not become one aria-describedby announcement. Inline confirmation callouts need an explicit decision between nonmodal semantics and a true [alert dialog](https://www.w3.org/WAI/ARIA/apg/patterns/alertdialog/).
