# Research modal consolidation patch

`opencoven-research-0.2.0-modal.patch` adapts the optional Research package to Coven Cave's shared Modal. It changes six private declarations (including the four Studio variants), reviews the five existing consumers, removes obsolete chrome, and retires the `wide` boolean. Feature data, remote-content consent, readers, generation actions and media behavior stay in Research. This patch is local delivery for issue #6200; it is not an upstream release.

The input is the unchanged `@opencoven/research` 0.2.0 release tarball referenced by package.json. Its original SHA-512 integrity remains in pnpm-lock.yaml. `patchedDependencies` in pnpm-workspace.yaml applies the tracked patch during normal and frozen installation. The lockfile pins the patch hash separately. pnpm's supported configuration is documented at [patchedDependencies](https://pnpm.io/10.x/settings#patcheddependencies).

To reproduce or update the patch, extract that integrity-verified original tarball into separate original and edited staging directories, apply the tracked patch to the edited copy with `git apply`, and change the edited `src` files. Do not edit node_modules as the deliverable. Run `node scripts/research/build-modal-patch.mjs <edited-package-directory>` to regenerate the nine changed compiled modules and six copied styles, then run `node scripts/research/check-modal-patch.mjs <edited-package-directory>`. The generator uses the repository's pinned esbuild and rewrites both static and dynamic relative TypeScript imports to compiled `.js` paths.

Generate a unified diff between the original and edited package trees with `a/` and `b/` path prefixes, including changed source, compiled modules and styles. Replace the tracked patch, run `pnpm install --lockfile-only`, preserve the original tarball integrity if pnpm omits it while refreshing the URL dependency, and run `pnpm install --frozen-lockfile`. Then run `node scripts/research/check-modal-patch.mjs`, `pnpm check:modals`, `pnpm typecheck`, and the production build. Compare a second generator run byte-for-byte against the first compiled output. A source-only patch is insufficient because production imports `dist`.

The initial generated patch failed the production build because a selector-filter setter retained empty selectors and the first import rewrite omitted dynamic imports. Both generator defects were corrected; the compiled-package checker explicitly rejects those cases. Preserve the failed build log and distinguish successful installation or source parsing from a successful production build and rendered acceptance.

Recovery on 2026-10-27 applied the archived 0.1.0 modal diff cleanly to the integrity-verified 0.2.0 tarball, regenerated the compiled files, and retained current main dependency/security versions. The archived patch remains available in the recovery tag; it is not an active dependency patch.
