## Current defect and alternatives

The transport harness signals only the root and awaits stream closure. Current-main preflight used the exact production function and real processes: a 100 ms deadline reported success after 7.115 seconds when a child retained output after root exit. Root-only signals had no effect. Merely marking the deadline would retain the hang; closing streams would lose evidence; signaling a vanished root's reused group would violate ownership. Reusing the long-lived mobile backend owner would conflate finite command exit status with backend lifecycle. Use a finite POSIX group anchor that remains alive across root exit and controls its own group instead.

## Design

Add `scripts/native-harness-command.py` as the private process-group anchor and `scripts/native-harness-command.mjs` as its finite Node API. The Node API is `runNativeCommand({ command, args, cwd, env, logPath, receiptPath, timeoutMs = 600000, signal, onLine })`. It resolves with a structured receipt only for a zero command result, complete output and verified owned cleanup; all other outcomes reject with the receipt attached. The harness retains its existing labels/logs and stage reporting. Its cancellation AbortController requests anchor cleanup before fixture teardown.

The anchor must be its own process group/session leader before executing anything. It launches the actual command within that private group, holds the group identity across root exit, observes group quiescence and services a bounded stdin control channel. Timeout/cancellation sends a graceful group signal from the live anchor itself; a still-running group is killed after the unchanged full five-second graceful-shutdown allowance. A separate maximum 1000 ms observation phase replaces the former unbounded post-kill wait; it only verifies terminal output/process state and cannot admit further successful command execution. The anchor never accepts an arbitrary PID/group target. An absent or invalid anchor cannot authorize signaling another process. The parent observes completion and group emptiness without sending group signals from stale receipts. Normal command failure preserves its real exit status. Deadline/cancellation remain failures even if the command later exits zero.

Keep stdout/stderr connected to the existing log until genuine closure. Missing acknowledgement, remaining processes, log failure or output that cannot close within the command deadline plus its five-second grace and 1000 ms terminal-observation bound produces incomplete failure with retained diagnostics, never success. A descendant that deliberately leaves the private session is outside admitted group ownership; do not signal it from an unproven PID, and report incomplete output rather than silently accepting it. Preserve any partial log and owner receipt.

Darwin inventory failures return zero with errno rather than a negative count; reject permission/interruption uncertainty and distinguish confirmed absence. Read only the admitted group, clear stale errno before each query, and never use an empty-looking failed census as cleanup proof. [Apple libproc implementation](https://github.com/apple-oss-distributions/xnu/blob/main/libsyscall/wrappers/libproc/libproc.c) defines this return contract.
