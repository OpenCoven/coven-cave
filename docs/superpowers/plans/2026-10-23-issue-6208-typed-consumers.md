## Retry contract

Revision editing must retain the reviewed source document, patch, expected revision and adoption key together until its outcome is known. Re-reading a newer document to reconstruct an uncertain command can change its payload under the same key. The command adapter therefore accepts an explicit reviewed source and never performs that reconstruction. The definition route now carries this source and the revision-editing client retains it with the pending serialized command in browser-tab session storage across remounts and reloads. Storage failure refuses mutation rather than discarding identity. The expected revision remains Coven's concurrency guard; the supplied digest is consistency evidence, not authority.

Deletion is one intent per automation ID and reviewed revision, so the UI derives a stable key from those values. The route now requires both the revision and key and sends a typed tombstone without a pre-read. Creation uses separate deterministic keys for create-draft and revise-paused, following the released Research pattern; its route and UI now retain the creation intent and require a separate activation review.
