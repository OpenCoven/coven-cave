# Hosted pan diagnostic design

Nova is continuing #6064 to distinguish gesture issuance, outer recognizer transitions, native geometry and potential endpoint routing on the hosted runtime where the current candidate has failed. The original source is signed/pushed e9465e80c9d062ad579f3d1d24b0e83a2207dc15. This is Nova's implementation choice under the requested unattended execution; it is not an assertion that Val reviewed this design.

The next diagnostic uses the existing externally prepared, previously compiled DEBUG-only pan observer in ChatScrollTrace.swift and ChatScrollAnchor.swift. It activates only with the existing open trace file, observes the existing recognizer through addTarget/removeTarget, and never modifies routing, recognizer delegates, enablement, gestures, scroll offsets or insets. Preserve the original UI-test bytes and the full 7×3 strict matrix. Timer polling, synchronous writes and hit testing can perturb timing; a passing diagnostic cannot replace the original failing matrix.

Alternatives considered: repeating the unmodified hosted matrix would add no discriminating data; another local-only run would retain the 23F73/24B8117 versus hosted23F77 runtime gap; observing the hosted recognizer and potential endpoints adds bounded boundary evidence without a speculative product fix. Raw touch interception, swizzling or delegate changes are outside this approach because they alter the path under investigation. A hit test remains a potential recipient, never delivery acknowledgement. Passing hosted runs already have only eight outer interacting phases for nine synthetic gestures, so missing phases alone are insufficient.

Reuse the existing 240-second monotonic deadline, 1,600 pan reservations, 2 MiB shared byte cap, bounded metadata and per-attachment generation tokens. A write failure latches permanently and emits only CAVE_SCROLL_TRACE_WRITE_ERROR out of band. Missing, capped, partial or erroring traces stay incomplete. Metadata excludes text, accessibility values/labels/identifiers, URLs, payloads and addresses. Retain exact source, binaries, runtime and first failures. No profiler, live provider, physical or installed-user-app operation belongs to this run.

Add one independent fixed-marker collection step immediately after strict, before Release, with the selected destination guard and a status expression that also runs after a strict failure. Query only that simulator, the CovenCave process and the fixed marker over the previous 70 minutes. Use the existing native-command wrapper with 15 seconds plus 5/5/5 seconds of shutdown, within one minute; include the actual 30-second wrapper bound in the existing one-minute job reserve calculation. Preserve the 108-minute job, 1,080-second Debug and 3,600-second strict ceilings and all native selectors/retry policies. Retain scroll-pan-marker.log and scroll-pan-marker.receipt.json through the existing independent uploads/freeze. A query failure or unattributed marker is incomplete evidence, never zero-error proof. Timestamp/PID correlation is required before attributing a marker to a strict app launch.

Verify the collection and budget contracts fail before implementation, then pass with the change. Reuse the previously reviewed two-file observer only after confirming its canonical hashes match current source. Verify the native source contracts and normal-signature build/targeted test without changing the original test file, then obtain a fresh review of the concrete diff before any signed publication. One hosted run is for diagnosis; source restoration and any final uninstrumented acceptance remain separate future steps governed by the actual result.
