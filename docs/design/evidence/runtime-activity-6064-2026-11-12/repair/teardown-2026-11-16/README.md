This tagged implementation explains why the two boundaries may differ; it does not prove the exact earlier installed binary or the original failure's cause.

After a successful stop command, `observeOwnedProcessExit` accepts only a valid positive recorded PID and definitive `ESRCH` before one monotonic 5,000 ms deadline. It probes every 50 ms while presence remains; probe and scheduling costs consume the same budget. Invalid PID, permission/unknown errors, observation failure and deadline expiry fail closed. The observer sends only signal zero and never terminates the daemon. Stopped server/provider, absent daemon state/socket and successful root removal remain required. A failed stop does not admit an observation success. The first version of this regression had an unbounded test-wait mistake: its timeout/interruption, owned-process absence audit and preserved root are retained separately. Review required bounded readiness/socket/probe/exit waits and cleanup targeting only that directly forked child; the corrected regression implements those guards.
