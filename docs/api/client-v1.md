# Client v1 API

Client v1 is Cave's owner-local API for native OpenCoven clients. Clients find
the active Cave listener through the discovery record, complete a human-approved
pairing, and exchange the one-time pairing secret for a bearer credential.

## Discovery

Cave publishes `client-v1-discovery.json` beneath `COVEN_CAVE_HOME`, or
`$COVEN_HOME/cave` when no Cave-specific home is configured. The record is a
mode-`0600`, owner-only file with this shape:

```json
{
  "version": 1,
  "endpoint": "http://127.0.0.1:3020",
  "pid": 12345,
  "nonce": "per-listener nonce",
  "startedAt": "2026-08-22T20:00:00.000Z"
}
```

Accept only a live owner-local process and a path-free loopback HTTP endpoint.
Cave replaces the record atomically and removes it on shutdown only when the
stored nonce still belongs to that listener.

## Public pairing routes

| Method | Route | Purpose |
|---|---|---|
| `GET` | `/api/client/v1/health` | Read API version, capabilities, and service health. |
| `POST` | `/api/client/v1/pairing/requests` | Create a five-minute pairing request. |
| `GET` | `/api/client/v1/pairing/requests/{id}` | Poll status using `x-coven-pairing-secret`. |
| `POST` | `/api/client/v1/pairing/requests/{id}/exchange` | Exchange an approved request once for a bearer credential. |

Create requests use this JSON body:

```json
{
  "appName": "OpenCoven Chat",
  "installationId": "stable-installation-id",
  "scopes": ["chat:read", "chat:write"]
}
```

Supported scopes are `chat:read`, `chat:write`, `conversations:write`,
`attachments:write`, `tasks:write`, and `github:write`. Request only the scopes
the client needs. Cave rejects non-loopback creation and exchange requests;
caller-supplied locality markers are stripped before Cave stamps verified
loopback requests.

The create response contains `requestId`, a one-time `secret`, and `expiresAt`.
Send that secret in `x-coven-pairing-secret` when polling and exchanging. An
exchange can return `pairing_pending`, `pairing_denied`, `pairing_expired`, or a
replay conflict. A successful exchange returns the bearer exactly once.

## Envelopes and credentials

Public route successes contain `apiVersion`, `minimumClientVersion`,
`capabilities`, and `data`. Errors contain the same compatibility metadata and
an `error` object with a stable `code`, bounded message, optional details, and a
`retryable` flag. HTTP status follows the error code; rate-limit responses also
include reset metadata.

Use the issued bearer only from native secure storage and send it as the client
authorization credential on scoped routes. Cave persists a SHA-256 bearer hash,
never the bearer itself. Revoked credentials fail authorization immediately.

The authenticated admin routes under `/api/client/v1/admin/` are Cave-internal
Settings endpoints, not client integration endpoints. Do not call them from a
paired client.

## Security boundary

- Client v1 discovery and pairing are owner-local, not a LAN or public API.
- Pairing secrets expire after five minutes and are single-use.
- Approval, denial, credential listing, and revocation require the authenticated
  Cave admin session; mutations also require a same-origin request source.
- Do not log or render pairing secrets, bearer values, authorization headers, or
  their hashes.

The exported machine contract is generated by
`node scripts/export-client-v1-contract.mjs`; verify it with `--check` after a
contract change.
